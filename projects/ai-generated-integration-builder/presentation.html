SLIDE 01 / Prototype vision

AI-Generated Integration Builder

A developer workspace to create connectors, supervise agents, review generated code and test safeguards.

The developer problem

Every SaaS API creates repeat engineering work. Authentication, user and activity schemas, pagination, resilience and incomplete documentation vary by provider.

Generated TypeScript package

API client; authentication setup; users and activity; error handling; pagination; structured logs.

The prototype promise

Generate faster. Keep developers in control. Catalog, chatbot and ownership; seven agents and three approval gates; 15 files, traces and sandbox tests. Demo only, read-only, no auto-deploy.

SLIDE 02 / Pain points + assumptions

Four pain points. Four explicit MVP boundaries.

Trustworthy developer assistance, not a promise of autonomous integration with every API.

Repeated API plumbing

Teams rebuild auth, clients, pagination, retry logic and logging for every vendor.

Client-rendered docs

JavaScript-rendered API portals can prevent static extraction.

Unclear usage semantics

User inventory and event activity do not necessarily reveal login history or paid-seat usage.

Verification & recovery

Missing files, API failures and unsafe redirects require observable checks and safe retries.

MVP boundaries

Developers own custom integrations; defaults are system-managed. HTTPS REST and read-only users/activity. Calendly events are a derived proxy, not license or login data. Demo model works without a key; real Gemini needs a key; sandbox tests are simulated.

Reported test evidence

6/6 automated groups passed; Calendly demo: three approvals, 15 files, review-ready status.

SLIDE 03 / Implemented architecture

API evidence → supervised connector

React catalog + Express APIs; checkpointed seven-agent workflow, three approvals, editable artifacts and simulated tests (as described in the deck).

API inputs

Documentation URL, REST API reference, OpenAPI JSON/YAML or labeled Calendly fixture; HTTPS and SSRF safety gate.

Evidence + policy

Validate doc structure → classify direct/proxy/missing capabilities → plan scopes and mapping.

Agent pipeline

Docs; capabilities; planner; auth + client; users + activity; errors + paging; security + tests.

Control gates

Capabilities, auth and scopes, code review; then sandbox tests. Pause, resume, cancel and retry.

Safety boundary

15 editable files, traces, ZIP and simulated sandbox. No production auto-deploy; API and model secrets stay server-side.

SLIDE 04 / Solution MVP

From onboarding to review-ready

The supplied deck reports a verified Calendly demo: seven stages, three approvals and 15 generated TypeScript files.

Onboard

Asha login, repeatable tour and searchable category catalog.

Create

Chat asks name, description and category; assigns owner.

Validate

Safe docs URL, OpenAPI or labeled Calendly fixture; select model.

Generate

Approve checkpoints, pause/retry, edit code and export ZIP.

Review

Traces, static checks and 12 simulated sandbox cases; release review.

Critical decision

Unverified API data is labeled, never fabricated. Unsafe URLs and security failures block progress. Demo sandbox only; no automatic deployment; ephemeral serverless state.
